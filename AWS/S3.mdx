- Making a bucket is just a little bit of button clicking
- cli
  - refer [cli](./aws%20cli.mdx)

```bash
# Set the bucket name for this terminal session
BUCKET="MY_BUCKET"

# List your buckets
aws s3 ls

# List objects at the bucket's root
aws s3 ls "s3://$BUCKET/"

# Upload a file
aws s3 cp ./hello.txt "s3://$BUCKET/hello.txt"

# Upload with a different object key
aws s3 cp ./hello.txt "s3://$BUCKET/notes/greeting.txt"

# List objects under a prefix
aws s3 ls "s3://$BUCKET/notes/"

# Download an object
aws s3 cp "s3://$BUCKET/notes/greeting.txt" ./downloaded.txt

# Upload all files in a directory
aws s3 cp ./my-folder/ "s3://$BUCKET/my-folder/" --recursive

# Preview files that would be uploaded or updated
aws s3 sync ./my-folder/ "s3://$BUCKET/my-folder/" --dryrun

# Upload new or changed files from a directory
aws s3 sync ./my-folder/ "s3://$BUCKET/my-folder/"

# Inspect an object's metadata
aws s3api head-object --bucket "$BUCKET" --key "notes/greeting.txt"

# Delete one object
aws s3 rm "s3://$BUCKET/notes/greeting.txt"
```

  - when I downloaded from the web page

This is what a signed url looks like

```md
https://<bucket>.s3.<region>.amazonaws.com/<object-key>
?X-Amz-Algorithm=<value>
&X-Amz-Content-Sha256=<value>
&X-Amz-Credential=<value>
&X-Amz-Date=<value>
&X-Amz-Expires=<value>
&X-Amz-Security-Token=<value>
&X-Amz-Signature=<value>
&X-Amz-SignedHeaders=<value>
&response-content-disposition=<value>
```

To presign via the cli

```bash
aws s3 presign "s3://ruins-test-bucket2/s3.mdx" --region us-east-1 --expires-in 300
```

- you can specify time not usage count, so this can't be single use etc
- max lifetime can be 7 days on private presigned urls ( or earlier if the creds that sign it expire earlier )

### How do I make a public link?

- note that public downloads have additional costs as well
- the default settings when creating a new bucket has ACL disabled so it cannot be public as is, you need to modifyt that first
  - ruins-test-bucket2 -> permissions -> block public access -> edit
  - 4 options there which are just
    - block new ACL
    - block any ACL
    - block new policies
    - block any policy

Polcies are the new thing, much more granular. This is what the policy looks like that made this specific file public for me

They jave a statement editor as well but in the end all it does it generate json in a very convoluted way.

```json
{
  "Effect": "Allow",
  "Principal": "*",
  "Action": "s3:GetObject",
  "Resource": "arn:aws:s3:::ruins-test-bucket2/s3.mdx"
}
```

- principal = who
- resource = arn, note that s3 buckets have no region in arn, they are globally unique
- action = `s3:GetObject` -> what operation

note that it is a list of statements and since ARNs support wildcards, you can easily support a public folder to make things easier.

With the changes in place, this link now works ( https://ruins-test-bucket2.s3.us-east-1.amazonaws.com/s3.mdx )
